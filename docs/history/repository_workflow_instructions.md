# Dual Repository Workflow Instructions

This project manages its codebase and compiled build assets in two separate Git repositories to prevent the main history from getting bloated with build artifacts.

## 1. Repositories Overview

*   **Main Repository ("Source")**
    *   **Path**: Root (`c:/my_project/myclass2026-main2/`)
    *   **Remote URL**: `https://github.com/mrahmedmosaadgh/myclass2026.git`
    *   **Branch**: `main3`
    *   **Purpose**: Contains all source code, logic, and raw resources (Vue, PHP, etc.).

*   **Build Repository ("Assets")**
    *   **Path**: `c:/my_project/myclass2026-main2/public/build/`
    *   **Remote URL**: `https://github.com/mrahmedmosaadgh/myclass2026_build.git`
    *   **Branch**: `main`
    *   **Purpose**: Contains *only* the compiled static assets generated by `npm run build` (JS chunks, CSS, Manifest).

## 2. Main Repository Workflow (Standard Development)

When making code changes:

1.  **Edit Code**: Modify files in `resources/`, `app/`, etc.
2.  **Verify**: Run tests or checks.
3.  **Commit & Push**:
    ```bash
    # In Root Directory
    git add .
    git commit -m "feat: Your descriptive message"
    git push origin main3
    ```

## 3. Build Repository Workflow (Deployment/Release)

When you need to update the production assets (after verifying code changes):

1.  **Generate Build**:
    ```bash
    # In Root Directory
    npm run build
    ```
    *This command compiles assets and places them into `public/build/`.*

2.  **Navigate to Build Repo**:
    ```bash
    cd public/build
    ```

3.  **Commit & Push Build Assets**:
    ```bash
    # Check status (you should see many changes/untracked files)
    git status
    
    # Stage all changes
    git add .
    
    # Commit
    git commit -m "chore: update build assets"
    
    # Push to build remote
    git push origin main
    ```

4.  **Return to Root**:
    ```bash
    cd ../..
    ```

## 4. Important Notes

*   **Do NOT commit `public/build` contents to the Main Repository.** The `.gitignore` in the main repo should exclude `public/build` (except possibly the `.git` folder structure itself if it's a submodule, but typically it's ignored).
*   **Always pull both** if switching machines to ensure source and assets are synced.
*   **Asset Bloat**: The build repo will grow large over time. This is expected and isolated from the source history.
